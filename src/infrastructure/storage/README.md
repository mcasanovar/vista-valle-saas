# Room image storage boundary

`contracts.ts` defines the room-image port: public URL lookup, metadata listing, and server-side upload/removal. Every object must be under `rooms/<room id>/`, use a safe filename and a MIME-matching `avif`, `jpg`, `jpeg`, `png`, or `webp` extension. The room id itself is a safe slug (letters, digits, `-`, `_`) rather than a strict UUID, so the same contract serves both real production rooms and the demonstration rooms used in mock. Upload bytes are validated before an adapter sees them; the maximum is 5 MiB.

`mock.ts` starts empty per instance, isolates each in-memory map, has no commercial images, and makes no network request. `server.ts` is server-only: the explicit `mock` context returns that map without instantiating any SDK client. In `production`, room images are stored in Cloudinary under the `room-images/` root folder: `cloudinary.config()` is called lazily from `CLOUDINARY_CLOUD_NAME`/`CLOUDINARY_API_KEY`/`CLOUDINARY_API_SECRET`, uploads use `uploader.upload` with an explicit `public_id`, removal uses `uploader.destroy`, listing uses `api.resources` with a folder `prefix`, and public URLs are built with `cloudinary.url`. Application authorization must precede any production write in the calling service.
